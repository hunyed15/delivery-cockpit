# cockpit-break-loop · 修了又犯的 bug

**何时用**：同一个问题修过两次还在犯，或修完别处又坏（对应 Trellis 的 break-loop）。

**目的**：停下来找根因类别，而不是再修一遍症状。

## 步骤
1. 写清三件事：症状、之前修过什么（哪个提交/哪次回执）、为什么没生效。
2. 归因到类别：缺测试 / 契约没定义 / 状态机缺口 / 平台差异 / 人的操作（选一个，别写"综合原因"）。
3. 给出防复发机制：加一条测试、加一道门禁、或写一条规范（用 `cockpit-spec`）。
4. 落地机制后，再修 bug 本身。
5. 回执里写：根因类别 + 机制 + 验证方式。

## 产出
- 根因说明
- 防复发机制（测试/门禁/规范）

## 硬约束
- 不允许只修症状
- 不允许"下次注意"当机制
- 机制要能被下一次自动执行

> 这些命令是驾驶舱自己的流程实现：Trellis 只作为数据来源（`.trellis/tasks`、`.trellis/spec`、审核账本），**不调用 `trellis` CLI**。
