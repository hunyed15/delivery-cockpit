# cockpit-spec · 规范沉淀

**何时用**：本轮学到了一条可复用的约定、踩过一次坑、或发现现有规范与实现不符（对应 Trellis 的 update-spec / before-dev）。

**目的**：让下一轮 / 下一个人不用重新踩坑。

## 步骤
1. 先读：`.trellis/spec/` 里相关条目（没有就跳过，不造目录结构）。
2. 写之前先判断类型：编码约定 / 数据契约 / 流程约束 / 已知坑。
3. 写成可执行的句子（"做什么 + 为什么 + 违反会怎样"），不要写"要注意质量"这种空话。
4. 写进 `.trellis/spec/` 对应文件；如果项目不用 Trellis 规范，写进 `docs/spec/`。**只追加或精修，不整篇重写。**
5. 在回执里写清改了哪条规范、为什么。

## 产出
- 规范条目（spec 文件）+ 回执

## 硬约束
- 不写空话
- 不改别人的既有结论：有冲突就并列写清两种做法的取舍
- 不顺手重构整个 spec

> 这些命令是驾驶舱自己的流程实现：Trellis 只作为数据来源（`.trellis/tasks`、`.trellis/spec`、审核账本），**不调用 `trellis` CLI**。
