# cockpit-check · 质量门自检

**何时用**：准备写回执说"这步做完了"之前，或准备提交/发版之前（对应 Trellis 的 check）。

**目的**：把"我以为做完了"变成清单：哪几项有证据，哪几项没有。

## 步骤
1. 测试：`test-report.json` 是否存在、是否比本轮改动新、`failed` 是否为 0。
2. 审核：账本本轮 `blocking` 是否为 0、有没有未处置问题。
3. 验收：`acceptance.json` 里本轮迭代的条目是否都有证据、有没有 `stale`。
4. 发布：`release.json`（如果这一轮要发）的产物是否存在、sha256 是否匹配。
5. 规范：这次改动是否违背 `.trellis/spec/` 里的约定（只读检查，不改 spec）。
6. 输出：通过项 / 缺口项 / 建议先补哪一项。**缺口不许用文字圆过去。**

## 产出
- 一份自检清单（通过 / 缺口）

## 硬约束
- 不伪造测试结果
- 不把未处置审核问题算通过
- 缺口存在时不许写 completed 回执蒙混

> 这些命令是驾驶舱自己的流程实现：Trellis 只作为数据来源（`.trellis/tasks`、`.trellis/spec`、审核账本），**不调用 `trellis` CLI**。
