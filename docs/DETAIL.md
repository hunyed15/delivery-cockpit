# 交付驾驶舱（delivery-cockpit）

一个 DSH 插件：把项目的真实状态收拢成一屏，回答**做到哪了、卡在哪、下一步做什么、用什么能力**。

## 它做什么

- **左侧栏「交付」整页**：项目总览（工作区列表，空目录也可见）→ 详情一屏四区
  - 项目名片 & 迭代头：项目名、技术栈（读文件探测）、本地启动命令、当前迭代、账本健康
  - 唯一下一步：状态机给出的唯一动作 + 理由 + 本阶段推荐能力 + 可直接执行的指令（可复制）
  - 迭代进度：冷启动（初始化 / 搭骨架）+ 迭代环（想清楚 / 看原型 / 写代码 / 挑毛病 / 验效果 / 发出去）
  - 人话账本：最近执行回执、待人工决策置顶、损坏行提示
- **两个强类型工具**
  - `cockpit_report`：Agent 每完成（或卡住）一步写一条回执，DSH 负责校验参数，插件只追加写
  - `cockpit_init`：初始化 `.trellis/` 与 `.dsh/plugin-state/`，释放 `RULES.md` / `project.json` / `playbook.json` / `acceptance.json`；幂等，`dryRun` 默认只预览

## 用法

1. 在任意工作区打开会话，左侧栏点「交付」。
2. 项目还没初始化时，下一步会给「初始化」；点按钮先看预览（dry-run），确认后落盘。
3. 按面板给的「下一步」在对话里推进；每一步做完让 Agent 调一次 `cockpit_report`。
4. 面板 8 秒自动刷新，也可点「刷新」。

## 边界与限制（如实写明）

- **只写 `.dsh/plugin-state/`**（初始化时额外建一个空 `.trellis/` 目录）。不改你的源码、不自动改 `.gitignore`（只给一行可复制提示）。
- **不生产业务数据**：进度来自回执、验收表、`.trellis` 任务与审核账本；读不到就显示 `—` / 「待确认」，不猜、不补 0。
- **审核账本是可选数据源**：没装审核插件或没有账本时，跳过「挑毛病」判定并在数据缺口里说明，不会假装"没问题"。
- **技能/MCP 存在性检测**：只能看到当前 profile 真正可用的能力；读不到时显示"无法检测"，不谎报缺失。
- **"谁在做什么"目前不显示**：DSH 宿主没有向插件开放 Agent Teams 任务板接口，Phase 1 不接并行视图。
- **一键发送至对话尚未接入**：Phase 1 提供可复制的指令原文，避免替你做无法确认的发送。
- **写接口的信任边界**：`POST /init` 与 `POST /approve-prototype` 只能作用于 DSH 已登记的工作区，且只写 `.dsh/plugin-state/` 与一个空 `.trellis/`；跨源请求被拒绝。但 DSH 的本地 HTTP 端口对同机进程不额外验身份，所以**本机进程**理论上可以触发这两个写接口。这是本地工具的共同边界，不是"人工批准"的密码学保证。

## 安装

```powershell
plugin_manager(action: "install_bundle", target: "D:\\Coding\\dsh-plugins\\dsh-project-cockpit")
```

需要 DSH `>=0.2.2-rc.3 <0.3.0`。与 `@hunyed15/project-cockpit`（v3.x，面板 id `project-cockpit`）可以并存：本插件用独立行 id `delivery-cockpit`。
