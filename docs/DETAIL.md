# 交付驾驶舱（delivery-cockpit）

一个 DSH 插件：把项目的真实状态收拢成一屏，回答**做到哪了、哪个功能做完/没做完/有 bug、下一步做什么、用什么能力**。

## 它做什么

- **左侧栏「交付」整页**：项目总览（工作区列表，空目录也可见）→ 详情一屏四区
  - 项目名片 & 迭代头：项目名、技术栈（读文件探测）、本地启动命令、当前迭代、账本健康
  - 唯一下一步：状态机给出的唯一动作 + 理由 + 本阶段推荐能力 + 可直接执行的指令（可复制）
  - 迭代进度：功能进度 `x/y` + 冷启动（初始化 / 搭骨架）+ 迭代环（想清楚 / 看原型 / 写代码 / 挑毛病 / 验效果 / 发出去）
  - **功能账 & 缺陷账**：按 PRD 的功能条目列出 **状态（已完成 / 有阻塞 / 进行中 / 待验收 / 未开始 / —）**、待修 bug 数、验收通过数、最近进展；未归属的 bug 单列；执行回执折叠在下方
- **三个强类型工具**
  - `cockpit_report`：Agent 每完成（或卡住）一步写一条回执，DSH 负责校验参数，插件只追加写；可选 `feature_ids` 把回执挂到 PRD 功能上
  - `cockpit_init`：初始化 `.trellis/` 与 `.dsh/plugin-state/`，释放 `RULES.md` / `project.json` / `playbook.json` / `acceptance.json`；幂等，`dryRun` 默认只预览
  - `cockpit_acceptance`：按 PRD 功能起草验收条目（`feature_ref` + 人话标题/步骤/期望），**只追加**——已有条目的 `result`/`evidence` 绝不覆盖，那是人的判断与证据

## 功能账怎么算（重要：只认结构，不猜自由文本）

**功能清单**只从 `prd.md` 的受控结构里提取：

```markdown
## 功能需求

### FR-1 信号采集（P0）
### FR-2 检索与打分（P1）
```

- 只有这一节（或全文兜底的 `### FR-N` 标题）里的条目才算功能；代码围栏里的示例不算。
- 没有这个结构时，面板会直说「没识别到功能条目」并给格式提示，**不会用启发式把标题当功能**。
- 功能的**状态**由三路证据推导，缺哪路就显示 `—`，不补 0：
  - 验收条目（`acceptance.json` 里 `feature_ref: "FR-1"`）**pass + 有证据** ⇒ 已完成
  - 审核账本里归属到该功能的未处置 blocking（按路径前缀匹配）⇒ 有阻塞
  - 回执声明 `feature_ids: ["FR-1"]` ⇒ 进行中 / 待验收
- **验收结果在面板里点**：「验收清单」每条都有 `通过 / 失败 / 阻塞 / 撤销`。点「通过」必须填证据（截图路径，如 `shots/a1.png`；或 `https://` 预览链接）——Host 会校验项目内文件**真的存在**，编造的路径会被拒绝（`evidence-not-found`）。失败/阻塞可以不附证据，撤销会把结果与证据一起清空。
- **回执自动归属**（可解释、可覆盖）：回执没写 `feature_ids` 时，按它的 `write_scope`/`artifacts`（以及所属任务的 `relatedFiles`）与功能路径锚点做前缀交集推断；任务标题里写了 `FR-3` 的，它的 `relatedFiles` 就是该功能的锚点。展开行会写明"其中 N 条自动归属"与锚点来源；**写了 `feature_ids` 的以自报为准，不做推断**。
- 附属规则：没有关联路径的功能，待修列显示 `—`（不是 0）；验收表属于别的迭代时不参与判定。

## 用法

1. 在任意工作区打开会话，左侧栏点「交付」。
2. 项目还没初始化时，下一步会给「初始化」；点按钮先看预览（dry-run），确认后落盘。
3. 按面板给的「下一步」在对话里推进；每一步做完让 Agent 调一次 `cockpit_report`，改代码时带上 `feature_ids`（如 `["FR-3"]`）与 `write_scope`。
4. 面板走到「生成验收清单」时，指令会点名还缺哪几条 `FR-x`：让 Agent 调 `cockpit_acceptance` 一次写入条目骨架（result 留空）。
5. 你在面板「验收清单」里逐条点 `通过 / 失败 / 阻塞`：通过必须填证据（截图路径或 URL），Host 会校验文件真实存在；点错可以「撤销」。
6. 跑审核（`claude_review`）后，bug 会按路径自动归属到功能；归属不到的进「未归属」。
7. 面板 8 秒自动刷新，也可点「刷新」。

## 边界与限制（如实写明）

- **只写 `.dsh/plugin-state/`**（初始化时额外建一个空 `.trellis/` 目录）。不改你的源码、不自动改 `.gitignore`（只给一行可复制提示）。
- **不生产业务数据**：功能状态来自 PRD 结构 + 回执 + 验收表 + 审核账本；读不到就显示 `—` / 「待确认」，不猜、不补 0。
- **PRD 是"人读版"，不是被解析的自由文本**：只有 `### FR-N` 结构参与功能账；PRD 里其他描述不会变成功能条目。
- **bug 归属靠路径前缀**：回执 `write_scope` 决定功能的文件范围；没写 `write_scope`（或没写 `feature_ids`）的回执不参与归属，bug 会进「未归属」。
- **审核账本是可选数据源**：没装审核插件或没有账本时，待修列显示 `—` 并在数据缺口里说明，不会假装"没问题"。
- **技能/MCP 存在性检测**：只能看到当前 profile 真正可用的能力；读不到时显示"无法检测"，不谎报缺失。
- **"谁在做什么"目前不显示**：DSH 宿主没有向插件开放 Agent Teams 任务板接口，Phase 1 不接并行视图。
- **一键发送至对话尚未接入**：Phase 1 提供可复制的指令原文，避免替你做无法确认的发送。
- **写接口的信任边界**：`POST /init` 与 `POST /approve-prototype` 只能作用于 DSH 已登记的工作区，且只写 `.dsh/plugin-state/` 与一个空 `.trellis/`；跨源请求被拒绝。但 DSH 的本地 HTTP 端口对同机进程不额外验身份，所以**本机进程**理论上可以触发这两个写接口。这是本地工具的共同边界，不是"人工批准"的密码学保证。

## 安装

```powershell
plugin_manager(action: "install_bundle", target: "D:\\Coding\\dsh-plugins\\dsh-project-cockpit")
```

需要 DSH `>=0.2.2-rc.3 <0.3.0`。与 `@hunyed15/project-cockpit`（v3.x，面板 id `project-cockpit`）可以并存：本插件用独立行 id `delivery-cockpit`。
