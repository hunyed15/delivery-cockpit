# 项目驾驶舱 · 功能设计

> 2026-11-20 · 完整功能设计（产品视角）
> 插件：`@hunyed15/project-cockpit`

## 1. 一句话

**把项目真实状态收拢成一屏，让人一眼知道：做到哪了、卡在哪、谁在干、下一步做什么。**

它不生产业务数据，也不另存状态；它读已有工具产出的事实，归一、投射、并给出唯一动作。

## 2. 谁在用、什么时候用

用户画像：非技术创始人 / 独立开发者，多项目，以 AI 为主要开发者。

每天打开 DSH 时问的问题：

| # | 问题 | 对应界面区 |
|---|---|---|
| 1 | 项目到哪了？ | 生命周期 + 三本账 |
| 2 | 卡在哪？ | 三本账（缺陷）+ 下一步 |
| 3 | 下一步做什么？ | 下一步 |
| 4 | 谁在干、会不会撞？ | 并行 |

前三个问题是单线开发的；第 4 个只在多 agent 并行时出现——但它一旦缺失，并行就会退化成"一个 agent 干到底"。

## 3. 设计原则

1. **不生产数据，只归一与投射。** 功能来自 trellis 任务，缺陷来自审核账本，会话来自宿主服务。加一个数据源 = 加一个适配器，不改视图。
2. **视图层不认识数据源。** 视图只认四类事实（功能 / 缺陷 / 阶段门 / 会话），永远不知道哪个文件、哪个插件产的。
3. **不给"看起来合理"的数字。** 读不到就显示 `—` 或"待确认"，绝不默认 0、不猜状态、不解析自由文本算进度。
4. **一步一个动作。** 主按钮只有一个；需要人决策的事交回对话，不在面板里发明快捷通道。
5. **同一屏口径一致。** 数据不可信时，chip、下一步、阶段门、表格一起降级，不能一半说"无问题"一半说"可能偏低"。

## 4. 一屏信息架构

```
┌───────────────────────────────────────────────────────────────┐
│ 项目名 · [待修 3 / 无待修 / 待确认] · 项目切换 · 更新于 · 刷新   │  ← 数据可信度
├───────────────────────────────────────────────────────────────┤
│ 异常横幅（仅在有数据问题时出现，可重试）                        │
├───────────────────────────────────────────────────────────────┤
│ 下一步：修复并复检                                             │
│   指令原文（标识符等宽）  ← 可直接粘贴执行                      │
│   理由 · 上次发送                              [去对话发送][复制][摘要] │
├───────────────────────────────────────────────────────────────┤
│ 生命周期：想清楚→定规格→搭骨架→写代码→挑毛病→验效果→发出去       │
│   当前门一句话 + 依据（可展开七道门明细）                        │
├───────────────────────────────────────────────────────────────┤
│ 三本账                                                          │
│   功能（= trellis 任务）  │ 状态 │ 作用域 │ 待修 │ 最近轮次      │
│   未归属缺陷（匹配不到功能的缺陷）                               │
├───────────────────────────────────────────────────────────────┤
│ 并行：N 个在跑 / 共 M 个会话 · 撞车预警                          │
│   会话 │ 目录 │ 状态 │ 创建于                                    │
└───────────────────────────────────────────────────────────────┘
```

## 5. 各区功能

### 5.1 数据可信度（顶部 + 横幅）

- **三态 chip**：`待修 N`（有阻塞）/ `无待修问题`（读到了且干净）/ `状态待确认`（数据不完整——账本异常或读取失败）。
- **异常横幅**：列出最多 3 条原因 + 剩余条数；带「重试」。
- **降级是整屏的**：一旦进入"待确认"，下一步改「先确认数据」并禁用主按钮，阶段门改「待确认」，表格缺陷列显示 `—`。

### 5.2 下一步

三层结构，缺一不可：

| 层 | 内容 | 作用 |
|---|---|---|
| 动作名 | 人话（修复并复检 / 复检本轮修复 / 跑第一次审核 / 跑提交门禁 / 初始化） | 做什么 |
| 指令原文 | 可直接执行的文本，标识符等宽 | 怎么做 |
| 理由 | 为什么是它 | 可反驳 |

状态机（优先级从高到低）：

| 条件 | 动作 |
|---|---|
| 项目未初始化 | 初始化 trellis |
| 有未处置 blocking | 修复并复检 |
| 有已标记 fixed 待复检 | 用 range 复检 |
| 从未审核 | 跑第一次 full |
| 全绿 | 跑提交门禁 |

### 5.3 生命周期（七阶段）

| 阶段 | 判据（推断） |
|---|---|
| 想清楚 | spec 文件数 > 0（近似，文案必须标"近似"） |
| 定规格 | `.trellis/spec/**` 文件数 |
| 搭骨架 | 项目已初始化 |
| 写代码 | 存在 in_progress / completed 任务 |
| 挑毛病 | 有审核轮次 **且无未处置 blocking** |
| 验效果 | 第二版接入（恒未完成） |
| 发出去 | 第二版接入（恒未完成） |

- 展示：一条 7 段进度线 + 当前门一句话 + 依据；明细默认收起。
- 「第二版接入」的门用**虚线**，与"没做"的实心浅灰区分。
- 当前门只能有一个；每道门必须有 `basis`。

### 5.4 三本账

**功能账**（= trellis 任务）

| 列 | 来源 |
|---|---|
| 功能名 | `task.title` |
| 状态 | `task.status` → 进行中 / 已完成 / 未开始 |
| 作用域 | `task.relatedFiles`（缺失则 `—`） |
| 待修 | 归属到该功能的未处置 blocking 数 |
| 最近轮次 | 该功能账本的最后轮次 + verdict |

**缺陷账**

- 每个功能的缺陷数来自审核账本（口径：`failOn` 取报告 `meta.failOn`，缺失回退 `critical/important`；处置必须轮次匹配）。
- 点击/展开可看最多 3 条：严重度 + 标题 + `文件:行`。
- **归属规则**：`issue.file` 按路径前缀匹配 `task.relatedFiles`。匹配不上的进「未归属」单列——如实显示，不硬塞。

**门禁账**

- 最近一次 gate 的结果与快照一致性（复用审核插件的账本语义）。
- 截断的 full pass 不算通过。

### 5.5 并行

| 列 | 来源 |
|---|---|
| 会话 | `sessionQuery.readTitleSnapshots`；子代理标层级 |
| 目录 | `SessionHeader.cwd` 与项目根比对 → 主工作区 / 其他目录 |
| 状态 | `ctx.sessions.list()`（内存态最权威） |
| 创建于 | `SessionHeader.createdAt` |

- **范围**：`cwd` 在项目根下，或父会话在项目根下（worktree 会话属于后者）。
- **撞车预警**：两个"运行中"的会话在同一目录 → 横幅点名（同目录并行必然互相覆盖）。
- **worktree 不跑 git 判定**，界面说"其他目录"，不假装能识别 worktree。
- 上限 20 行，超出提示"只列出最近 N 个"。

## 6. 四类事实与数据源

| 事实 | 来源 | 关键字段 | 缺失时 |
|---|---|---|---|
| feature | `.trellis/tasks/*/task.json` | `title / status / subtasks / relatedFiles` | 任务表为空，显示"未初始化" |
| defect | `<task>/review/review-N.json`、`dispositions.jsonl` | `review.issues[].severity/file/line/key/issue`、`meta.failOn`、`meta.round` | 缺陷列 `—`，不显示绿 0 |
| gate | 上面两者 + `.trellis/spec/**` | 文件数、任务状态、轮次数 | 整屏「待确认」 |
| session | `sessionQuery.listSessions()` + `ctx.sessions.list()` | `header.cwd / parentSession / origin / delegationDepth / createdAt` | 并行区显示原因，其余不受影响 |

## 7. 架构分层

```
适配器层   trellis · 审核账本 · sessions ·（将来）任务板 / 验收结果 / 外部插件
             每个源：{ id, read(), 版本假设, 降级文案 }
   ↓ 只读、可选、互不依赖；一个源坏了只影响它自己
归一化层   四类事实（纯函数，可单测）
   ↓
视图层     五区（只认归一化事实）
   ↓
行动层     唯一动作 + 两步发送
```

**硬约束**：视图层不得 import 任何适配器；新增数据源只允许新增适配器。

## 8. 行动层

- 面板是 root scope，拿不到会话输入能力，因此**两步**：点击 → 跳回对话，输入框上方通栏确认 → 走用户自己的发送通道。
- 通栏三键：`填入输入框`（主）/ `发送` / `忽略`；两者都会替换草稿，必须明示。
- 记「上次发送」时间（本地），区分"还没做"与"刚做完、账本未更新"。
- 将来的动作（同一条通道，不新增特权）：`催一下`（向指定会话 steer）、`开始集成`（发给集成会话）。

## 9. 降级矩阵

| 缺失/异常 | 可信度区 | 下一步 | 生命周期 | 三本账 | 并行 |
|---|---|---|---|---|---|
| 无 `.trellis` | 待确认 | 初始化 | 首门未完成 | 空态 | 正常 |
| 账本坏行 | 待确认 + 原因 | 先确认数据（禁用） | 待确认 | 缺陷列 `—` | 正常 |
| 读取失败（HTTP/超时） | 待确认 + 旧数据时间 + 重试 | 先确认数据（禁用） | 待确认 | 保留旧数据并标时间 | 正常 |
| 无 `sessionQuery` | 不受影响 | 不受影响 | 不受影响 | 不受影响 | 显示原因 |

## 10. 非目标

- 不重造待办（dsh-todos 之类）、不做甘特图、不做趋势图/热力图
- 不写项目里任何文件；要存只存 `.dsh/plugin-state/`
- 不解析 PRD 文本算完成度、不跑 git 判定 worktree、不给"看起来像"的数字
- 不做多项目并列看板（跨项目字段预留，不实现）

## 11. 里程碑与验收

| 步 | 内容 | 验收标准 |
|---|---|---|
| **M1** | 功能账 + 缺陷按 `relatedFiles` 归属 + 未归属单列 | 真实仓库上"每功能待修数"与手工核对账本一致；未归属数量正确；匹配不到时显示 `—` |
| **M2** | 并行视图（已具备） | 会话树/目录/活否正确；同目录双活报撞车；缺服务时降级 |
| **M3** | 任务板接入：认领 + 写作用域 | 派活后显示"谁在做什么"；两个任务 scope 有交集 → 跨目录冲突预警 |
| **M4** | 行动：催一下 / 开始集成 + 集成后自动 gate | 点击后目标会话真的收到消息；集成后自动产生审核轮次 |
| **M5** | 外部源（dsh-todos / 验收结果）——按需 | 每加一个源必须有降级分支与单测 |

## 12. 风险

| 风险 | 对策 |
|---|---|
| 每个源一份格式依赖 | 适配器隔离 + 每源必备"读不到"分支与文案 |
| 路径前缀匹配可能误挂缺陷 | 未归属单列 + 界面标注"按路径推断" + 不做模糊匹配 |
| 面板信息过载 | 每区有行数上限与截断提示；不上图表 |
| 数字造假（历史上出现过：读错路径导致 blocking 恒为 0） | 禁止默认值兜底；每个字段的读取路径必须有针对真实样本的回归测试 |

## 13. 待定（需要产品决策）

1. **功能的粒度**：一个 trellis 任务 = 一个功能，是否够用？还是需要"任务 → 功能"的映射表？
2. **未归属缺陷**是否允许手工指派到功能（要写状态文件，与"不写项目文件"冲突）。
3. 跨项目视图何时需要（当前单项目多 agent）。
